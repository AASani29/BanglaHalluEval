# BenHalluEval dataset

The complete benchmark used in the paper *BenHalluEval: A Multi-Task Hallucination Evaluation Framework for Large Language Models on Bengali*. It covers four tasks, each with two tracks:

- **Track A:** gold, ground-truth correct answers. The expected judge verdict is "No" (not hallucinated).
- **Track B:** hallucinated candidates generated by GPT-5.4. The expected judge verdict is "Yes".

| Task | Track A (gold) | Track B (hallucinated) | Hallucination types (Track B) |
|---|---|---|---|
| Question Answering | `QA/qa_gt_1000.csv`: 1,000 | `QA/qa_hallu_4000.csv`: 4,000 | 4 × 1,000 |
| Bangla-English Code-Mixed QA | `CodeMixed_QA/codemix_gt_1000.csv`: 1,000 | `CodeMixed_QA/codemix_hallu_4000.csv`: 4,000 | 4 × 1,000 |
| Summarization | `Summarization/summarization_gt_1000.csv`: 1,000 | `Summarization/summarization_hallu_3000.csv`: 3,000 | 3 × 1,000 |
| Mathematical Reasoning | `Mathematical_Reasoning/reasoning_gt_1000.csv`: 1,000 | `Mathematical_Reasoning/reasoning_hallu_1000.csv`: 1,000 | 5 × 200 |
| **Total** | **4,000** | **12,000** | 12 types |

These counts match Table 1 and Table C.1 of the paper.

All files are UTF-8 CSV. Bengali text is in Bengali script, and code-mixed text is Bangla-English in Latin script.

## Files and columns

### Question Answering (seed: TyDiQA-GoldP, Bengali)

- **`qa_gt_1000.csv`**: `id`, `context` (supporting passage), `question`, `correct_answer`
- **`qa_hallu_4000.csv`**: `id`, `source_id` (the `id` of the gold item), `pattern` (hallucination type), `context`, `question`, `right_answer`, `hallucinated_answer`
  - `pattern` values: `factualness`, `comprehension`, `specificity`, `inference` (1,000 each)

### Bangla-English Code-Mixed QA (same 1,000 seeds as QA, converted with GPT-5.4)

- **`codemix_gt_1000.csv`**: `id`, `context`, `question`, `correct_answer` (original Bengali), `codemix_context`, `codemix_question`, `codemix_answer`
- **`codemix_hallu_4000.csv`**: `id`, `source_id`, `pattern`, `codemix_context`, `codemix_question`, `codemix_answer`, `hallucinated_answer`
  - `pattern` values: as for QA (1,000 each)

### Summarization (seed: BanglaCHQ-Summ)

- **`summarization_gt_1000.csv`**: `id`, `question` (the source consumer-health query, i.e. the document), `summary` (gold summary)
- **`summarization_hallu_3000.csv`**: `id`, `source_id`, `pattern`, `document`, `right_summary`, `hallucinated_summary`
  - `pattern` values in the file: `Intrinsic`, `Non-factual`, `Factual Contradiction` (1,000 each). See "Open points" below.

### Mathematical Reasoning (seed: SOMADHAN)

- **`reasoning_gt_1000.csv`**: `question_id`, `question`, `answer` (gold chain-of-thought solution), `hallucinated_len` (reasoning-chain length used for sampling)
- **`reasoning_hallu_1000.csv`**: `id`, `source_id`, `question_id`, `hallucination_type`, `question`, `answer` (gold chain), `reasoning_len`, `hallucinated_chain`, `error_step`, `error_type`, `hallucinated_answer`, `raw_response` (raw GPT-5.4 output), `parse_error`
  - `hallucination_type` values: `arithmetic_slip`, `formula_misapplication`, `invalid_deduction`, `hallucinated_intermediate_fact`, `semantic_drift` (200 each)

### Other files

- **`docs/BanHalluEval_Annotation_Guidelines.pdf`**: the guidelines given to the three human annotators.
- **`MANIFEST.csv`**: for every file, the row count, its SHA-256 checksum, and the project path it was copied from.

## Where these files came from

This folder holds **copies**. The original files are still in place, so the project's scripts and notebooks keep working. `MANIFEST.csv` lists each original path, and the checksums confirm that each copy is byte-identical to its source.

| File here | Copied from |
|---|---|
| `QA/qa_gt_1000.csv` | `BanglaHalluEval Datasets/qa_gt_1000.csv` |
| `QA/qa_hallu_4000.csv` | `Hallucination Generated Answers/qa_hallu_4000.csv` |
| `CodeMixed_QA/codemix_gt_1000.csv` | `Codemix/Main dataset/codemix_1000.csv` (renamed) |
| `CodeMixed_QA/codemix_hallu_4000.csv` | `Hallucination Generated Answers/codemix_4000.csv` (renamed) |
| `Summarization/summarization_gt_1000.csv` | `Summarization/1000 Selected Samples/summarization_gt_1000.csv` |
| `Summarization/summarization_hallu_3000.csv` | `Hallucination Generated Answers/summarization_hallu_3000.csv` |
| `Mathematical_Reasoning/reasoning_gt_1000.csv` | `Reasoning/1000 Selected Samples/reasoning_gt_1000.csv` |
| `Mathematical_Reasoning/reasoning_hallu_1000.csv` | `Hallucination Generated Answers/reasoning_hallu_1000.csv` |

The QA, Summarization and Reasoning files are also identical to the copies in `supervisor_package/data/`.

### Not included, on purpose

- **`Summarization/3000 Candidate Answers/summarization_hallu_3000.csv`** (1.1 MB). It has the same name as the real file, but it is a faulty version: `source_id` and `right_summary` are empty in all 3,000 rows, and the `document` column holds QA questions, not health queries. The correct file is the 4.8 MB version from `Hallucination Generated Answers/`. Consider deleting or renaming the faulty one so it can't be picked up by mistake.
- Model outputs and evaluation results (e.g. `*_labeled.csv`, `*_eval_results.csv`, `Codemix/Results/`). These are judge verdicts, not benchmark data.
- Pilot samples (`pilot_50_samples/`, `Codemix/Pilot Testing/`) and seed-selection intermediates (`Sample Selection for QA/`, `Sampling/`).
- Human annotation labels. No per-item annotation file was found in the project; only the guidelines are here.

## Open points before a public release

1. **Summarization type names.** The file uses `Intrinsic`, `Non-factual` and `Factual Contradiction`. The paper uses *Fabricated Content*, *Non-Factual Addition* and *Direct Contradiction*. Confirm which file label is which paper type, then either rename the values or document the mapping here.
2. **Reasoning column name.** In `reasoning_gt_1000.csv`, the column `hallucinated_len` holds the gold chain length used for sampling. A clearer name, such as `reasoning_len`, would avoid confusion.
3. **Internal columns.** `raw_response` and `parse_error` in `reasoning_hallu_1000.csv` are generation logs. Keep them for transparency, or drop them from the public release.
4. **Human annotation labels.** The paper reports three-annotator labels on the full benchmark (Appendix I). If those labels should be released, add them to this folder.
5. **Licence.** The seed datasets (TyDiQA-GoldP, BanglaCHQ-Summ, SOMADHAN) have their own licences, which the release must respect. Add a `LICENSE` and a citation entry before depositing on Zenodo or Hugging Face.
